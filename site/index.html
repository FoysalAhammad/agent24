Getting Started

Three minutes from install to your first completed task.

1. Install & open

Install Agent 24, open it, and grant the accessibility permission when prompted (required for screen understanding and UI dumping).

2. Connect a provider

Run /connect and pick from 13 pre-configured providers — OpenCode Zen, Pollinations (free), OpenAI, Anthropic, Google, Groq, DeepSeek, Mistral, xAI, Together, OpenRouter, HuggingFace, GitHub Models. Free options work with zero setup.

3. Choose a model

/model lists every model of the connected provider with capability flags: supportsTools, supportsImages, supportsReasoning, supportsStreaming.

4. Start working

Just type the task in natural language:

> build a calculator app with history
> find every TODO in src/ and summarize
> refactor utils.js and run the tests

  → ask   → confirmation popup → wait for user
  → allow → action runs

Evaluation order

  2. Check wildcard (*) permission
  3. Default: allow (build) / ask (plan)

Error handling

HTTPTypeUser message
401AuthenticationInvalid API key. Check Settings > Models.
402PaymentQuota exhausted. Add credits or switch provider.
403Access deniedNo permission for this model.
404Not foundModel not available. Try another.
429Rate limitToo many requests. Wait and retry.
5xxServer errorProvider unavailable. Retrying…

Retry: max 3 attempts, exponential backoff 2s → 4s → 8s (429: 5s → 10s → 15s), auto-fallback to Pollinations on 4xx/5xx.

Skills

Markdown instruction files loaded into the system prompt on demand.

Location

~/.config/agent24/skills/<name>.md

Usage

Load with the skill tool or ask the agent directly — it pulls the file into context:

{ "tool": "skill", "params": { "name": "settings-customization" } }

Structure

  • One markdown file per skill
  • Loaded skills are listed at the bottom of the system prompt
  • Related assets can sit next to the file
  • List everything with /skills

Example

# settings-customization
How to modify agent24.json safely: keys, defaults,
restart behavior and rollback steps.

MCP

Model Context Protocol — connect external tool servers.

Registering a server

{
  "server": "my-server",
  "instructions": "shown to the model in the system prompt",
  "tools": [ { "name": "create_issue", "inputSchema": { ... } } ]
}

Calling any of these tools routes the result back to the model.

Naming

MCP tools are prefixed with mcp_{serverName}_{toolName} so they never collide with built-ins.

mcp_github_create_issue
mcp_slack_send_message

Flow

  1. Server registers tools & instructions
  2. Instructions join the system prompt
  3. Tool definitions join the API tool list
  4. Model calls mcp_* → routed to the server

Typical uses: telemetry, auto-backup before edits, audit logging, custom notifications.

Sessions

Every conversation is an isolated session with its own database.

Lifecycle

startNewSession()  → id "session_" + timestamp → metadata → session database → event
loadSession(id)    → set current → load messages → update timestamp → event
deleteSession(id)  → drop database + folders + metadata → clear memory → event

Storage

DatabasePath

Queue

If the session is busy, messages go into a ConcurrentLinkedQueue and show Queued (N pending) — they run right after the current task completes.

Troubleshooting

SymptomFix
401 errorsRe-enter API key: Settings > Models, or /connect
429 rate limitWait — auto backoff 5s/10s/15s; or switch provider
Model not respondingTry another model with /model; free fallback is Pollinations
Agent stuck in a loopPermission key doom_loop triggers recovery
Context too longRun /compact — chat history stays
UI dump failsEnable accessibility service, then retry ui_dump
Command not found/help lists commands; custom ones live in ~/.config/agent24/commands/
Session feels slowCheck the queue; switch to a faster model (e.g. openai-fast)

Still stuck?

Open a session and ask — the agent can read its own logs via bash and the global database at ~/.local/share/agent24/databases/.
