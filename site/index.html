Agent 24

Agent 24 is an open-source AI assistant for Android. It writes and edits code, runs shell commands, works with files and documents, searches the web and finishes multi-step tasks — end to end, from your phone.

Quick start

  1. Install the APK from GitHub Releases and open Agent 24.
  2. Connect a provider with /connect — free models work with zero setup.
  3. Pick a model — /model.
  4. Describe the task in plain language. The agent takes it from there.

Getting Started

From install to your first completed task in about three minutes.

1. Install

Download the latest APK from GitHub Releases, install it and open the app. When prompted, grant the accessibility permission — it is required for screen understanding and UI dumping. No account or sign-up is needed.

2. Connect a provider

Run /connect and choose one of the 12 pre-configured providers (see Providers). Free-tier models are available out of the box; paid providers only need an API key, entered once and stored in the Android Keystore.

3. Choose a model

/model lists every model of the connected provider together with its capability flags: supportsTools, supportsImages, supportsReasoning and supportsStreaming.

4. Start working

Describe the task in natural language — in English, Bangla or Banglish:

> build a calculator app with history
> find every TODO in src/ and summarize
> refactor utils.js and run the tests
> make me a PDF invoice from this data

Error handling

HTTPTypeUser message
401AuthenticationInvalid API key. Check Settings → Models.
402PaymentQuota exhausted. Add credits or switch provider.
403Access deniedNo permission for this model.
404Not foundModel not available. Try another.
429Rate limitToo many requests. Wait and retry.
5xxServer errorProvider unavailable. Retrying…

Retry policy: up to 3 attempts with exponential backoff (2s → 4s → 8s; for 429: 5s → 10s → 15s). A failing free-tier model is automatically retried once on a backup model, with a notice in the reply.

Markdown instruction packs loaded into the system prompt on demand.

Location

~/.config/agent24/skills/<name>.md

Usage

Load with the skill tool, or just ask — the agent pulls the file into context:

{ "tool": "skill", "params": { "name": "glassmorphism" } }

Bundled skills

SkillPurpose
settings-customizationHow to modify configuration safely
design-stylesSelector & heuristic over the design corpus
minimalism … maximalism10 self-contained UI design styles (bento-grid, glassmorphism, liquid-glass, claymorphism, brutalism, neumorphism, skeuomorphism, spatial-ui and more)

When you ask the app to build any UI, the agent first asks you to pick one of the 10 design styles (or describe your own) and then follows that skill for the whole build. List everything with /skills.

Structure

  • One markdown file per skill (or a directory with SKILL.md)
  • Loaded skills are listed at the bottom of the system prompt
  • User-edited skill files are never overwritten by app updates

MCP

Model Context Protocol — connect external tool servers to extend the agent.

Registering a server

{
  "server": "my-server",
  "instructions": "shown to the model in the system prompt",
  "tools": [ { "name": "create_issue", "inputSchema": { ... } } ]
}

Naming

MCP tools are prefixed with mcp_{serverName}_{toolName} so they never collide with built-ins:

mcp_github_create_issue
mcp_slack_send_message

Flow

  1. The server registers tools and instructions.
  2. Instructions join the system prompt.
  3. Tool definitions join the API tool list.
  4. A model call to mcp_* is routed to the server.

Sessions

Every conversation is an isolated session with its own database.

Lifecycle

startNewSession()  → id "session_" + timestamp → metadata → session DB → event
loadSession(id)    → set current → load messages → update timestamp → event
deleteSession(id)  → drop DB + folders + metadata → clear memory → event

Storage

DatabasePath
Session DB~/.local/share/agent24/sessions/{id}/session.db
Global DB~/.local/share/agent24/databases/agent24_global.db

Auto features

FeatureTrigger
Auto-titleFirst user message → 3–5 word title
Auto-summarySession switch → conversation summary
Auto-compactionTokens > 80% → summarize & compact
Auto-queueSession busy → queue, then drain

If the session is busy, messages wait in a queue and show Queued (N pending) — they run right after the current task completes.

Troubleshooting

SymptomFix

Model not respondingTry another model with /model; a free fallback is offered automatically
Agent stuck in a loopThe doom_loop permission triggers recovery
Context too longRun /compact — chat history stays

Privacy Policy

Effective 10 October 2026 · Version 2.0 · Privacy contact: GitHub Issues

This is the privacy policy of Agent 24 ("the app"), an open-source Android application. It explains what user data the app accesses, collects, uses, handles and shares; with whom; and what control you have. The same policy is available inside the app (first-launch consent screen and Drawer → Privacy Policy). We do not sell personal or sensitive user data. Your conversations never pass through servers run by the project.

Consent

On first launch the app shows this policy and asks for your consent before anything is collected. You must tap I Agree & Continue to proceed. Android runtime permissions (accessibility, camera and similar) are requested only when a feature you choose actually needs them.

No account. No registration. No advertising identifier. No data broker.

Persistent device identifiers

The app does not collect or use IMEI, IMSI, SIM serial numbers, the Android Advertising ID (AAID) or the App Set ID, and does not link any persistent device identifier to personal or sensitive user data or to resettable device identifiers.

What is sent to AI providers

When you send a message, the app forwards the message text, conversation context and any tool results the model requested to the provider you selected in Settings → Models, over TLS. Each provider's own privacy policy governs that transfer. The project does not relay conversations through its own servers. Removing your API key (Settings → Models → Remove) stops all further calls.

Third-party code and advertising

Components bundled with the app (PDF processing, on-device OCR, the terminal runtime) operate entirely on your device. No embedded SDK sells personal or sensitive user data from this app. When advertisements are shown, they are delivered through the project's own signed remote configuration — no third-party advertising SDK is embedded, no advertising identifier is collected, and no cross-app advertising profile is built.

Retention and deletion

Your data stays on your device for as long as you keep it. The project retains nothing on its own servers, and no account exists — so there is no server-side copy to delete. You can delete everything at any time:

  • In-app: Settings → Delete All Data
  • Full removal: uninstall the app — app-private data is removed with it
  • Keep a copy: Settings → Export Data (Markdown / JSON) before deleting
